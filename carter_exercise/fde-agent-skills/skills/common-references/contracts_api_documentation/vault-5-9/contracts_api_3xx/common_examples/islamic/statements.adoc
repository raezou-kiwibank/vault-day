= Statements

Financial products often produce statements which reflect the financial state of the account at the
end of a specified period. An example is a deposit account, which calculates an outstanding balance
for the statement period by summing the principal plus any fees and profit.

A statement can be generated by a Smart Contract within a scheduled event, making use of the
start_workflow api to send out an message to the Kafka topic with relevant data, so that the bank
may subscribe to it and pick up the message to send out the statement. By specifying a suitable time
range using the `@requires` decorator, the postings made on the account within the statement period
can be retrieved and made available to the hook.

Postings are retrieved according to their `value_timestamp`. The `value_timestamp` indicates the
time the committed posting should affect the balance. However, because Vault supports the backdating
of postings, postings could appear within the statement cycle even if they have been committed at a
later date.

Statements typically must be immutable for regulatory reasons and, once generated, they cannot be
changed. To guarantee this, you can filter posting instructions by their `insertion_timestamp` when
generating a statement, as this field indicates when the posting was committed to the posting
ledger. Postings can be filtered by this attribute and omitted if the `insertion_timestamp` is
outside the statement period.

[NOTE]
====
The `insertion_timestamp` is an attribute of the `PostingInstruction` and `PostingInstructionBatch`
types from API version 3.6+.
====
