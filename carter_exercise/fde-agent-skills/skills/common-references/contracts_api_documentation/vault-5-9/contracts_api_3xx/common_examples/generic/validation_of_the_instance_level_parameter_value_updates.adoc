= Validation of the INSTANCE level parameter value updates

Smart Contracts can have their `INSTANCE` level parameter values updated by a user. Before the
updated values are saved, they go through validation in Vault. Smart Contracts enable dynamic
adjustment of validation through the `pre_parameter_change_code` hook. If the hook is not defined in
the Smart Contract, validation is done using the originally declared parameters.

Here is a common example for updating parameter validation dynamically:

The bank might want to allow an extra overdraft for a customer who is considered a VIP. In that
case, the Smart Contract could increase the `max_value` metadata on NumberShape for
`overdraft_limit`. That would allow the bank to set the new value above the original limit.

[source,python]
----
parameters = [
    Parameter(
        name='overdraft_limit',
        level=Level.INSTANCE,
        description='Overdraft limit',
        display_name='Overdraft limit',
        default_value=Decimal(0),
        shape=NumberShape(
            min_value=0,
            max_value=100,
        ),
        update_permission=UpdatePermission.USER_EDITABLE
    ),
]

@requires(flags=True)
def pre_parameter_change_code(parameters, effective_date):
    is_vip = vault.get_flag_timeseries(flag='VIP').latest()
    if 'overdraft_limit' in parameters and is_vip:
        parameters['overdraft_limit'].shape = NumberShape(
            min_value=0,
            max_value=200,
        )
    return parameters
----

[NOTE]
====
A Smart Contract modifies the shape of the parameters passed in as an argument to the hook. Make
sure that you return the newly modified parameters, otherwise changes will have no effect on
validation in Vault. Only `INSTANCE` level parameter updates trigger the `pre_parameter_change_code`
hook on the account.
====
