= Overdraft Protection

Many US banks offer the overdraft protection feature for their customers, which links customer
checking (current) and savings accounts to extend a customer's spending allowance beyond their
checking account balance and overdraft.

Overdraft protection functionality can be implemented using
link:{baseURL}/reference/contracts/contracts_api_4xx/supervisor_contracts_api_reference4xx/hooks#pre_posting_hook[pre-posting hook supervision]. To ensure that Supervisor data fetching would have a minimal performance impact
on online postings, the `pre_posting_hook` does not support the postings data requirement and only
supports parameter and the optimised balances data fetcher requirements (see
link:{baseURL}/reference/contracts/contracts_api_4xx/concepts#about_optimised_data_fetching[About optimised data fetching]). The example below demonstrates how to link customer savings and checking
accounts in a plan, to increase the spending limit on a checking account.

Setting up a Supervisor Contract:

[arabic]
. Create the Supervisor Contract with the `pre_posting_hook`, then configure it to supervise the
checking account `pre_posting_hook` with `INVOKED` mode and the savings account with no hook
supervision (just linked to the Supervisor). (For `INVOKED` mode, see
link:{baseURL}/reference/contracts/contracts_api_4xx/common_types_4xx/enums#supervisionexecutionmode[SupervisionExecutionMode].)
. In the Supervisor Contract `pre_posting_hook`, fetch all checking and savings accounts `LIVE`
balances.
. Check the new posting instructions `balances` effect.
. Use the `get_hook_result` method to get the outcome of the checking account `pre_posting_hook`
execution.

[NOTE]
====
The Supervisor Contract `pre_posting_hook` will only be executed when the checking account is
targeted with new posting instructions, but can still fetch data from the savings accounts, which
are also supervised by this plan.
====

To supervise the Smart Contract `pre_posting_hook`, the Supervisor Contract code must specify a new
attribute `supervised_hooks` in the
link:{baseURL}/reference/contracts/contracts_api_4xx/common_types_4xx/classes#smartcontractdescriptor[SmartContractDescriptor].
This attribute currently only supports the `pre_posting_hook`.

[source,python]
----
supervised_smart_contracts = [
    SmartContractDescriptor(
        alias="savings", smart_contract_version_id="savings_contract_version_id"
    ),
    SmartContractDescriptor(
        alias="checking",
        smart_contract_version_id="checking_contract_version_id",
        supervised_hooks=SupervisedHooks(pre_posting_hook=SupervisionExecutionMode.INVOKED),
    ),
]
data_fetchers = [
    BalancesObservationFetcher(
        fetcher_id="live_balance",
        at=DefinedDateTime.LIVE,
    ),
]

@fetch_account_data(balances={"savings": ["live_balance"], "checking": ["live_balance"]})
@requires(data_scope="all", parameters=True)
def pre_posting_hook(
    vault, hook_arguments: PrePostingHookArguments
) -> Optional[PrePostingHookResult]:
    checking_account_vault = None
    new_checking_acc_postings_balance_net = Decimal(0)
    checking_acc_overdraft = None
    balance_key_committed = BalanceCoordinate(
        account_address=DEFAULT_ADDRESS,
        asset=DEFAULT_ASSET,
        denomination="GBP",
        phase=Phase.COMMITTED,
    )
    checking_acc_balance = Decimal(0)
    savings_accs_balance_list = []
    for acc, supervisee in vault.supervisees.items():
        if supervisee.get_alias() == "savings":
            savings_live_balances = supervisee.get_balances_observation(
                fetcher_id="live_balance"
            ).balances
            savings_accs_balance_list.append(savings_live_balances[balance_key_committed].net)
        if supervisee.get_alias() == "checking":
            checking_account_vault = supervisee
            new_checking_acc_postings = hook_arguments.supervisee_posting_instructions[acc]
            for new_checking_acc_posting in new_checking_acc_postings:
                new_checking_acc_postings_balance_net += new_checking_acc_posting.balances()[
                    balance_key_committed
                ].net
            checking_acc_overdraft = Decimal(
                supervisee.get_parameter_timeseries(name="unarranged_overdraft_limit").latest()
            )
            checking_live_balances = supervisee.get_balances_observation(
                fetcher_id="live_balance"
            ).balances
            checking_acc_balance = checking_live_balances[balance_key_committed].net

    # Handle a case where checking account is not on-boarded on-to the account.
    if not checking_account_vault:
        return

    # If checking account accepted the posting instructions - supervisor accepts
    # the posting instructions with no additional balance checks.
    account_rejection = checking_account_vault.get_hook_result()
    if not account_rejection.rejection:
        return
    # If there was some other rejection reason - supervisor rejects the posting instructions as well.
    if account_rejection.rejection.reason_code != RejectionReason.INSUFFICIENT_FUNDS:
        return SupervisorPrePostingHookResult(
            rejection=account_rejection.rejection,
        )
    # Get total savings balance available
    total_savings_balance = sum(savings_accs_balance_list)
    # Here we only have posting instructions that were rejected
    # because of insufficient funds in checking account.
    if (
        checking_acc_balance
        + total_savings_balance
        + new_checking_acc_postings_balance_net
        + checking_acc_overdraft
    ) < 0:
        return SupervisorPrePostingHookResult(
            rejection=Rejection(
                message="Checking and Savings accounts do not have sufficient funds.",
                reason_code=RejectionReason.INSUFFICIENT_FUNDS,
            )
        )
----

For posting instructions that target different accounts:

* the account's `pre_posting_hook` `posting_instructions` argument attribute will contain only those
that target the specific account
* The plan's `pre_posting_hook` `supervisee_posting_instructions` argument attribute will contain
all posting instructions that target accounts that have their `pre_posting_hook` supervised by the
plan

You can access the posting instructions for a particular `account_id` from the
`supervisee_posting_instructions` argument attribute by simply accessing list of posting
instructions by the `account_id` key. Then the `balances()` can be accessed on each individual
posting instruction for each different `account_id` without passing the `account_id` argument.

[source,python]
----
balance_key_committed = BalanceCoordinate(
    account_address=DEFAULT_ADDRESS,
    asset=DEFAULT_ASSET,
    denomination="GBP",
    phase=Phase.COMMITTED,
)
# Posting instructions targeting account "account_id"
supervisee_acc_posting_instructions = hook_arguments.supervisee_posting_instructions["account_id"]
# Net balance of posting instructions targeting account "account_id" with balance address `balance_key_committed`
supervisee_acc_postings_balance_net = Decimal(0)
for supervisee_acc_posting_instruction in supervisee_acc_posting_instructions:
    supervisee_acc_postings_balance_net += supervisee_acc_posting_instruction.balances()[
        balance_key_committed
    ].net
----
