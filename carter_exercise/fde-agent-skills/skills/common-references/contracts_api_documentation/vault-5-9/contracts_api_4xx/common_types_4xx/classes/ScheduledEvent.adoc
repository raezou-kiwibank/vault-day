= ScheduledEvent
:status: hidden

pass:q[`ScheduledEvent`]  

The native representation of a schedule which an event will adhere to.  

== Constructor:
pass:q[`ScheduledEvent(*, start_datetime, end_datetime, expression, schedule_method, skip)`]  

Constructs a new ScheduledEvent object.

Must be timezone aware using the pass:q[`ZoneInfo`] class and be based on the Account's operating timezone. If neither of these is set, link:{baseURL}/smart_contracts/contracts_api_4xx/smart_contracts_api_reference4xx/vault#events_timezone[vault.events_timezone]{empty} defaults to UTC. Note that the pass:q[`start_datetime`] is required for any new pass:q[`ScheduledEvents`] returned by pass:q[`activation_hook`] or pass:q[`conversion_hook`]. However, existing schedules will start from their last successful execution time and so the pass:q[`start_datetime`] for existing pass:q[`ScheduledEvent`]s in the pass:q[`conversion_hook`] must be omitted (or set to None, or remain unchanged), as any other value will result in an error. Otherwise it can be set as a field defined in the link:./../smart_contracts_api_reference4xx/metadata#events_timezone[Smart]{empty} or link:./../supervisor_contracts_api_reference4xx/metadata#events_timezone[Supervisor]{empty} Contract metadata. If neither of these is set, link:{baseURL}/smart_contracts/contracts_api_4xx/smart_contracts_api_reference4xx/vault#events_timezone[vault.events_timezone]{empty} defaults to UTC.

|schedule_method|pass:q[`Optional`][pass:q[`EndOfMonthSchedule`]]| The schedule definition for a recurring monthly event, represented as a native object. Either pass:q[`expression`] or pass:q[`schedule_method`] must be populated.
