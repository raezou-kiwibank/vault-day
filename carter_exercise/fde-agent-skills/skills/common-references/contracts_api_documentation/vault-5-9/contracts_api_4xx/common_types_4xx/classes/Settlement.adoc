= Settlement
:status: hidden

pass:q[`Settlement`]  


link:{baseURL}/reference/postings#settlement_chainable[Settlement]{empty} is a chainable Posting Instruction
that clears funds that have been previously authorised in a
link:#clienttransaction[ClientTransaction]{empty}. The Client Transaction being cleared is identified
by the pass:q[`client_transaction_id`] attribute.

To enable Posting Instruction methods that return indirect or output attributes
to work in unit tests, you must set private Posting Instruction attributes when
mocking Vault data. You can do this by calling pass:q[`_set_output_attributes()`] method
on the Posting Instruction class instance. To see an example,see our
link:{baseURL}/smart_contracts/contracts_api_4xx/development_and_testing#supervisor_contract_example_unit_test[Supervisor Contract example unit test]{empty}.

== Methods:
pass:q[`balances(*, account_id, tside)`]  

Returns the net balance changes to the Account caused by this Posting Instruction.
  

[width="100%", options="header"]
|===
|name|type|description
|account_id|pass:q[`Optional`][pass:q[`str`]]| The ID of an Account for which the balance changes should be returned. Does not need to be provided for historical Posting Instructions returned via pass:q[`vault`] methods or new Posting Instructions that the hook receives via arguments in pass:q[`pre_posting_hook`] and pass:q[`post_posting_hook`]. In these cases, the argument defaults to the pass:q[`account_id`] of the Smart Contract or the ID of the supervisee Account in Supervisor Contract. Only required when creating a Posting Instruction within a Contract, as these might contain instructions for multiple accounts. This also applies for PostingInstructionDirectives accessible in a Supervisor Contract via pass:q[`get_hook_result()`] method. 
|tside|pass:q[`Optional`][pass:q[`Tside`]]| The T-side of an Account which is used to calculate net balances. Does not need to be provided for historical Posting Instructions returned via pass:q[`vault`] methods or new Posting Instructions that the hook receives via arguments in pass:q[`pre_posting_hook`] and pass:q[`post_posting_hook`]. In these cases, the argument defaults to the pass:q[`tside`] of the Smart Contract or the pass:q[`tside`] of the supervisee Account in Supervisor Contract. Only required when creating a Posting Instruction within a Contract, as these might contain instructions for multiple accounts. It is not required for PostingInstructionDirectives accessible in a Supervisor Contract via the pass:q[`get_hook_result()`] method and defaults to the pass:q[`tside`] of the supervisee Account. 
|===

**Return Value:** pass:q[`BalanceDefaultDict`]  


The default balance dictionary where the key is the
link:{baseURL}/smart_contracts/contracts_api_4xx/common_types_4xx/classes#balancecoordinate[BalanceCoordinate]{empty} and the value is
a link:{baseURL}/smart_contracts/contracts_api_4xx/common_types_4xx/classes#balance[Balance]{empty} object which contains the debit,
credit and net balance changes for the Account. Accessing a non-existent key will
return a pass:q[`Balance`] object with zero debit, credit, and net balance changes.
