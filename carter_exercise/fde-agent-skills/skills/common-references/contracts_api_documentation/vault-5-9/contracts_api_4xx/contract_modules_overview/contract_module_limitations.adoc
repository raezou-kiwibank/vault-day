= Contract Module limitations

Contract Modules only require a declaration of the Contract Language API version in the metadata
(which must be the same major version as the Contract that imports it), but can optionally import
Python modules or custom types from `contracts_api` with the same restrictions that apply to other
Contract code.

[source,python]
----
from decimal import Decimal, ROUND_HALF_UP
from contracts_api import (
    BalanceCoordinate,
    DEFAULT_ADDRESS,
    DEFAULT_ASSET,
    Phase
)

api = '4.0.0'

ACCRUAL_DECIMAL_PLACES = 5

def round_accrual(amount: Decimal):
    pad = f'.{0:0{ACCRUAL_DECIMAL_PLACES}}'
    return amount.quantize(Decimal(pad), rounding=ROUND_HALF_UP)

def default_balance_coordinate():
    return BalanceCoordinate(DEFAULT_ADDRESS, DEFAULT_ASSET, "GBP", Phase.COMMITTED)
----

All custom types are now common to Smart and Supervisor Contracts, as well as Contract Modules - see
link:{baseURL}/reference/contracts/contracts_api_4xx/common_types_4xx[Common Contract types] section.

If the link:{baseURL}/reference/contracts/contracts_api_4xx/smart_contracts_api_reference4xx/vault/[Account Vault object]
is required by a Contract Module function, it must be passed in as an argument just as it
would be for a helper function in the Smart Contract itself.
